# 产品需求：橦云接口

## 背景

调试接口时，请求经常散落在 Apifox、Postman 或 IDE 的临时文件里。这些工具要么要账号和云端同步，要么不方便让 AI agent 直接改。

橦云接口把请求收成仓库里的纯文本。人和 agent 用编辑器改文件；桌面应用只负责打开、替换变量、发送和看响应。数据留在本机文件夹里。

## 谁在用

- 作者本人，在自己的电脑上调试 HTTP 接口
- 在这个仓库里改 `.http` 和环境文件的 AI agent

没有团队空间，没有分享链接，没有登录。

## 要解决的事

1. 请求可以被普通文本 diff 和评审。
2. 点一次就能把当前环境代入并发出请求。
3. 响应的状态、耗时、响应头和 JSON 正文能在旁边看清。
4. 密钥留在被 git 忽略的私有环境文件里，不进提交。

## 原则

- 文件是接口的唯一来源。应用不把请求另存成自己的数据库。
- 发送在本机 Rust 进程里完成，这样本地服务和任意主机都不受页面 CORS 限制。
- 示例和文档只出现中性的公开地址。
- MVP 把一条请求从文件送到响应看完，不扩展成接口管理平台。

## MVP 要有的

- 打开文件夹
- `.http` / `.rest` 文件和其中请求的树
- 环境切换，合并公共环境与私有环境，替换 `{{变量}}`
- 一键发送，展示状态码、耗时、响应头和整理后的 JSON
- `examples/` 中的 httpbin 示例，以及一份可提交的环境文件
- 解析器的单元测试

## 明确不做

- 账号、云同步、多人协作、评论
- 在应用里编辑并写回 `.http`（用编辑器或 agent 改文件，再用「重新读取」）
- 执行前置脚本和响应脚本
- Mock 服务、自动化断言、测试报告
- OAuth 登录流程、Cookie 罐、代理设置界面
- 从外部文件载入请求体

## 主流程

1. 打开桌面应用，打开一个含 `.http` 的文件夹（开发时可以直接打开 `examples/`）。
2. 在左侧选中一个请求，看替换后的地址、请求头和请求体。
3. 在顶部切换环境。地址里的 `{{host}}` 跟着变。
4. 点发送。右侧出现状态码、耗时、响应头和正文。JSON 会缩进显示。
5. agent 改完文件后，点「重新读取」，再发送一次。

## 文件契约

详见 [AGENTS.md](../AGENTS.md)。公共契约是 IntelliJ HTTP Client 的子集：`###` 分隔、`# @name`、`{{var}}` 替换、`http-client.env.json` 与 `http-client.private.env.json`。环境按每个请求文件自己的目录向上合并，兄弟目录的私有变量不会套到别的请求上。
